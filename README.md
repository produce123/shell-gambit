# Shell Gambit · 恶魔轮盘聚会版

一个**纯前端、零依赖、无需服务器**的 2–4 人联机霰弹枪轮盘小游戏。
直接把仓库传到 GitHub Pages 就能玩：一个人开房，其他人输入同一个房间号即可加入。

**在线玩：** https://produce123.github.io/shell-gambit/
（若你的账号配置了 Pages 自定义域名，也可用 https://home.prodhub.me/shell-gambit/ ）

> 灵感来自《Buckshot Roulette（恶魔轮盘）》，针对「朋友聚会、手机随手玩」重新设计：
> 随机座位、每轮随机装弹、7 种道具、纯前端 P2P 联机。

## 快速开始

### 在线玩（GitHub Pages）

打开部署地址即可。首页三个入口：

| 入口 | 说明 |
| --- | --- |
| **人机对局** | 单人也能玩，可选 2 / 3 / 4 人局，其余席位由 AI 补齐 |
| **在线对局** | 创建房间或输入房间号加入，2–4 人实时联机 |
| **游戏规则** | 完整规则与 7 种道具说明 |

首页底部可以自行开关 **音效** 与 **特效**（对局中的「☰ 菜单」里也能改），
开关状态记在浏览器本地。关掉特效后仍保留文字事件流与中央横幅提示，不会失去任何信息。

### 对局记录

对局界面下方是**可展开的对局记录**：默认收起，只把**最新的一条**顶在右边，
一眼就能看到刚发生了什么；点一下「对局记录」展开成可滚动的完整历史，
自动滚到最新一条，再点一下收起。展开状态也会记在本地。

> 收起时用 `justify-content: flex-end` 让最新一条留在可见区 ——
> 早期版本是从左边开始排，条目一多，最新的几条就被 `overflow: hidden` 裁掉了，
> 手机上根本看不到刚刚的操作。

联机步骤：

1. 点【在线对局】，先取一个**单字**名字（会显示在头像上）。
2. 房主点【创建房间】，把 5 位房间号发给朋友。
3. 朋友点【在线对局】→ 输入房间号 → 【加入】。
4. 房主点【开始对局】。人数不够时房主可以【添加 AI 补位】。
5. 大厅和牌桌上都可以点别人头像扔 🥚 鸡蛋 或 🌸 鲜花。

### 本地运行

因为用了 ES Module，直接双击 `index.html`（`file://`）会被浏览器拦掉，
需要用一个静态服务器打开（**部署到 GitHub Pages 时不存在这个问题**）：

```bash
node tools/serve.mjs 8080   # 然后浏览器打开 http://127.0.0.1:8080/
```

## 规则

### 基础玩法

- 2–4 人，每人 **5 点生命**，开局**随机**分配 1–4 号座位。
- 每一**轮**随机装填一批「实弹 / 空弹」混合弹序。
  **两种弹药各剩多少是公开信息，先后顺序严格保密。**
- 每轮由 **1 号座位**先行动（1 号已出局则由下一个存活座位开始）。
- 轮到你时：先摸牌，然后选择【对自己开枪】或【对别人开枪】。
- **空弹打自己**：不掉血，并且**保留回合**，可以继续操作（这是核心博弈点）。
- **实弹命中**扣 1 点血；锯短枪管时扣 2 点。血量归零立即淘汰。
- 弹匣打空后自动重新装填，回到新一轮。
- 最后活下来的唯一玩家获胜。

弹药数量规则：总发数 = 人数 × 2 ～ 人数 × 3 之间的随机数，
实弹发数在该总数内随机，但**至少 1 发**、且**至少留 1 发空弹**。
（例如 4 人局可能是 8～12 发，其中实弹 1～11 发。）

### 摸牌规则

- 牌堆共 **28 张**：7 种道具 × 4 张。
- 开局每人 2 张；之后每个回合摸 2 张，**全局第一回合只摸 1 张**。
- 手牌上限 **4 张**：回合开始前已有 3 张就只发 1 张，已有 4 张则不发。
- 摸牌堆少于 4 张时，弃牌堆洗匀后放到摸牌堆**底部**（不是顶部，避免刚弃的牌立刻被摸到）。
- 玩家被淘汰时，其手牌全部进入弃牌堆。

### 7 种道具

| 道具 | 效果 |
| --- | --- |
| 🔍 **放大镜** | 查看当前这一发是实弹还是空弹（**只有你能看到**） |
| 🔄 **逆转器** | 反转当前这一发子弹的真假（实弹↔空弹） |
| 💉 **肾上腺素** | 从一名对手手中**随机偷取**一张道具并**立刻使用** |
| 🍺 **啤酒** | 退出当前枪膛里的第一发子弹（**子弹类型公开**） |
| 🪚 **手锯** | 锯短枪管：下一发实弹伤害翻倍（打出空弹则浪费） |
| 🚬 **香烟** | 恢复 1 点生命值（上限 5，满血使用则浪费） |
| ⛓️ **手铐** | 封锁一名对手的下一回合 |

### 容易记错的细节（本作的明确裁定）

这些地方原版规则有歧义，本项目做了明确处理，并且每条都有单元测试覆盖：

- **放大镜**的情报是私有的，对手看不到。
- **逆转器**是公开动作：原本知道这一发的人，会同步知道它被反转了
  （否则先看再转就成了单向作弊）。
- **啤酒**退出的子弹类型是公开的（大家都能听到退弹的声音）。
- **手锯**只对下一发有效，**打出空弹也会浪费**；已经锯过时不允许重复锯。
- **香烟**满血使用等于浪费一张牌。
- **肾上腺素**偷不到对手的肾上腺素（防止无限递归）；
  偷到**手铐**时会再让你**选一次目标**；
  偷到的牌若**没有合法目标**（例如所有人已被铐住），则该牌直接进弃牌堆。
- **手铐**不能铐自己，也不能铐已经被铐住的人。
  被铐住的人**回合一开始就被跳过**，手铐在跳过的那一刻消耗掉，回合顺延给下一位能行动的人；
  如果除当前行动者以外的所有人**都被铐住 / 都被跳过**，回合**回到当前行动者身上**
  （2 人局里就是「他打完你、你被跳过、他接着打」），
  被跳过的人只能丢掉这一回合，**不会反向拿到一个回合**。
  手铐若一直没轮到消耗（例如弹匣先打空换弹了），会保留到下一轮继续生效。

## 联机是怎么做到的（没有任何服务器）

```
   房主（权威端）                客人 A              客人 B
        │                          │                    │
        │  ①公共信令通道交换 WebRTC 握手（房间号 = 主题名）  │
        │◄──── HELLO ──────────────┤                    │
        ├───── HOST_PRESENT ──────►│                    │
        │◄──── OFFER / ICE ────────┤                    │
        ├───── ANSWER / ICE ──────►│                    │
        │                          │                    │
        │  ② RTCDataChannel P2P 直连（星型拓扑，房主是中心） │
        │◄══════ 操作意图 ═════════►│◄══════ 操作意图 ═══►│
        ├══════ 各自私有的状态视图 ═►│                    │
```

- **信令**：多路公共通道并行使用（HiveMQ 等 MQTT over WSS + ntfy.sh），
  同一房间号即同一主题名，任何一条通道活着就能配对上。
- **传输**：优先 **WebRTC DataChannel 直连**；
  网络受限（对称 NAT、无公网）时自动降级为**中转模式**，经公共通道转发，**照样能玩**。
- **配对成功后**：一旦所有客人都直连成功，房主会主动断开公共信令。
  此时断网/关掉信令都不影响对局。
- **房主是权威端**：只有房主跑游戏引擎，其他人只发送操作意图，
  所以不可能出现两端状态不一致，也不可能靠改前端作弊。

### 三个必须解决的工程问题

1. **公共通道是 QoS 0（最多一次），消息会丢。**
   - 客户端操作带 `actionId`，没收到回执就重发，房主按 id 去重回放结果。
   - 客户端每收到一帧状态回一个 `STATE_ACK`，房主每 2 秒把**落后的人补齐**。
     这样丢帧不会让任何人卡在旧状态。
2. **公共 broker 限制同一 IP 的并发连接数。**
   - 一次开五六条连接反而会被集体踢下线，导致每个人活着的通道各不相同、互相收不到消息。
   - 所以改成**波浪式连接**：一次最多并发 2 条，够用即停；断了自动重连并重订阅。
3. **每条通道都可能被收到别人的私密数据。**
   - 只订阅「广播」和「发给我的」两个主题，**绝不订阅通配符**。
   - 服务端也只发送**裁剪后的视图**（`viewFor`）：公开血量/手牌张数/剩余弹数，
     私有手牌内容、私有放大镜情报、弹匣真实顺序。

## AI 是怎么想的

AI 与真人**看到的信息完全一样**：只有公开的血量、手牌张数、剩余各类弹药数量，
以及自己用放大镜看到的结果。它**读不到弹匣顺序，也读不到别人的手牌**，
**更不知道谁是真人、谁是 AI**——因此不会针对或保护任何人。

`aiDecide(state, playerId)` 与 `aiDecideFromView(view)` 共用同一个决策核心
`decideFrom()`，所以「AI 作弊」在结构上就不可能发生。

决策方式是对每个合法动作算期望值，主要考虑：

- **保留回合**的价值（空弹打自己能继续行动，是非常强的节奏）
- **击杀**收益、**自己掉血**的风险（血越少越保守）
- **威胁评估**：血多的、手牌多的、即将轮到的人更该被打
- **记仇**：被谁打过就略微更倾向还手，但**只是一个小权重**，会被局势分析覆盖
- 一点点随机噪声，避免每局都一模一样

「敢赌实弹 / 空弹」不是写死的，而是期望值算出来的结果：
当自己残血、对手即将行动时，AI 会更愿意赌一把。

## 项目结构

```
index.html              单页应用：所有界面都在这一个文件里
css/style.css           暗色极简样式，手机 / 平板 / 桌面自适应
js/
  main.js               入口
  engine/               游戏引擎（完全不碰 DOM，Node 里也能跑）
    constants.js        规则常量、道具定义
    rng.js              可复现的随机数（mulberry32）
    engine.js           状态机：装弹、发牌、7 种道具、回合与轮次、视图裁剪
  ai/ai.js              AI 决策（只吃公开信息 + 自己的私有情报）
  game/match.js         把引擎 + AI 编排成一场比赛（含 AI 思考延时）
  net/
    protocol.js         消息协议、房间号生成
    mqtt.js             极简 MQTT 3.1.1 over WebSocket（含自动重连）
    channels.js         公共信令总线（多通道 + 去重 + 波浪式连接）
    rtc.js              WebRTC 点对点链路（直连 / 中转自动降级）
    session.js          房主 / 客人 / 单机三种会话
  ui/
    app.js              界面主控：屏幕切换、大厅、牌桌渲染、动画播放
    icons.js            内联 SVG 图标（无图片文件）
    audio.js            WebAudio 现场合成音效（无音频文件）
    effects.js          飞行动画、枪口火光、伤害数字、横幅
tools/
  serve.mjs             本地静态服务器（仅开发用）
  cdp.mjs               极简 CDP 驱动，用来跑真实浏览器测试（仅开发用）
tests/
  rules.test.mjs        32 条规则单元测试
  sim.mjs               AI 自对弈压力测试（不变量 / 覆盖率 / 胜率均衡）
  net.test.mjs          真实公共通道的联机集成测试
  e2e.test.mjs          真实浏览器端到端测试（含 3 人联机与自适应布局）
```

**零运行时依赖、零构建步骤**：没有 `node_modules`、没有打包器，
所有 `js/**` 都是浏览器可以直接加载的 ES Module。

## 测试

```bash
node tests/rules.test.mjs        # 规则单元测试（32 条）
node tests/sim.mjs 20000         # 每种人数自对弈 20000 局，检查不变量
node tests/net.test.mjs          # 真实公共信令通道的联机集成测试
node tests/e2e.test.mjs          # 真实无头浏览器端到端测试
node tests/e2e.test.mjs layout   # 只跑自适应布局体检

# 直接对线上部署做端到端验证（不启本地服务器，直接打真实网址）
node tests/e2e.test.mjs https://produce123.github.io/shell-gambit/
```

也可以用 `npm run test:all` 一次跑完（需要本机装有 Chrome 或 Edge）。

验证涵盖：

- **规则正确性**：7 种道具的每个分支、牌数守恒（28 张永远不多不少）、
  边界与非法操作、以及「死锁」这一永久不变量。
- **AI 自对弈**：数十万局随机对局中不允许出现非法动作、死锁或状态损坏；
  胜率必须接近理论值（2 人 50/50、3 人各 1/3、4 人各 1/4），以此证明没有位置或身份偏向。
- **联机**：真实公共通道配对、完整对局同步、**客户端视野不泄露弹序与手牌**。
- **真实浏览器**：无头 Chrome 打开真实页面，3 个浏览器实例配对并打完整局，
  校验三家看到的公开状态与最终胜者完全一致；并检查控制台零报错。
- **一致性**：两家对局中每一步都要求「收敛到同一状态帧、且同一帧内容完全一致」
  （直接先后读取是有竞态的，所以判据是最终收敛而不是瞬时快照）。
- **界面自适应**：在 360×640 / 430×932 / 768×1024 / 1280×900 四种视口下
  校验无横向溢出、元素不跑出屏幕、按钮点击区域不小于 48px。

## 浏览器要求

需要支持 ES Module、WebRTC DataChannel 与现代 CSS 的浏览器：
Chrome / Edge 90+、Safari 15+、Firefox 90+。

部分网络环境（尤其是企业网络、某些移动运营商）会屏蔽公共 MQTT broker，
此时会自动尝试其它通道；如果全部不可用，会提示「连不上任何公共信令通道」。
这种情况下**同一局域网**通常仍可通过 WebRTC 直连完成配对。
